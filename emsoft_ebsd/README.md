# EMsoftData_work — Nickel EBSD Simulation Pipeline

This folder holds a full **EMsoft** simulation pipeline for Electron Backscatter
Diffraction (EBSD) on nickel, plus a set of Python/kikuchipy scripts that
validate the simulation against a real experimental scan and generate
derived datasets (a synthetic microstructure demo, denoising training pairs).

Folders are numbered in pipeline order. Each stage consumes the output
file(s) of the previous stage and produces the input file(s) for the next
one — the chain is:

```
00_crystal_structure
        │  (Ni.xtal)
        ▼
01_monte_carlo            EMMCOpenCL: simulate electron scattering in the crystal
        │  (Ni_MC.h5)
        ▼
02_master_pattern         EMEBSDmaster: build the full-sphere diffraction pattern
        │  (Ni_master.h5 / Ni_master_hires.h5)
        ▼
03_ebsd_pattern_simulation   EMEBSD: project master pattern onto a detector
        │  (Ni_EBSD.h5 / Ni_EBSD_sim.h5)         at chosen crystal orientations
        │
        ├──────────────► 04_microstructure_demo   (uses Ni_master_hires.h5 directly)
        │
        ├──────────────► 05_denoising_training_data (uses Ni_EBSD_sim.h5 + real patterns.h5)
        │
        └──────────────► 06_euler_angle_validation  (supplies the orientations that
                                                       03 simulates, and checks the
                                                       result against the real scan)
```

`06_euler_angle_validation` is drawn last but actually runs **first and last**:
it extracts the orientation list (`ni_angles.txt`) that `03` needs as *input*
before the EMEBSD run, and then compares `03`'s *output* back against the
real scan afterwards. It is the loop that closes the pipeline.

All `.nml` files are EMsoft input decks. Every filename written inside them
(`anglefile`, `masterfile`, `datafile`, `dataname`, `energyfile`,
`copyfromenergyfile`, `BetheParametersFile`, `tiff_prefix`) is resolved
**relative to `EMdatapathname`**, a path set once in
`~/.config/EMsoft/EMsoftConfig.json` — currently this repo's root. That is
why every `.nml` file below includes the subfolder name in these fields
(e.g. `masterfile = '02_master_pattern/Ni_master_hires.h5'`) even though the
`.nml` file itself lives elsewhere. The one exception is `xtalname`, which is
resolved against the separate `EMXtalFolderpathname` setting, currently
pointed at `00_crystal_structure/`.

## `00_crystal_structure/` — the crystal definition

The starting point of everything: a description of nickel's atomic lattice.
Nothing upstream of this; it is hand-authored / obtained once and never
regenerated by the pipeline.

| File | Type | Description |
|---|---|---|
| `Ni.xtal` | HDF5 | Face-centered-cubic nickel crystal structure: space group, lattice parameters, atom positions/occupancies. **Input to:** `01_monte_carlo/MCNi.nml` (`xtalname = 'Ni.xtal'`), which uses it to simulate how electrons scatter inside this specific lattice. |

---

## `01_monte_carlo/` — electron trajectory simulation (EMMCOpenCL)

**Input:** `00_crystal_structure/Ni.xtal`
**Output:** `Ni_MC.h5`, consumed by `02_master_pattern/`

Simulates ~10⁸ incident electrons scattering inside the Ni crystal at a
70° sample tilt and 20 keV beam energy, and records their energy/exit-angle
statistics. This is the physics groundwork the master pattern is built from
— it does not yet know about crystal orientation or a detector, only about
how electrons of each energy backscatter out of the material.

| File | Type | Description |
|---|---|---|
| `MCNi.nml` | EMsoft input deck | The actual config used: `xtalname='Ni.xtal'`, `mode='full'` (EBSD), `numsx=501`, `sig=70.0`, `EkeV=20.0`, `totnum_el=1e8`. Output field `dataname` points to `01_monte_carlo/Ni_MC.h5`. Run with `EMMCOpenCL MCNi.nml`. |
| `EMMCOpenCL.template` | EMsoft input deck (blank) | Generic, uncustomized version of the same file (`xtalname='undefined'`, `dataname='MCoutput.h5'`) — kept as a reference/starting point for creating new Monte Carlo runs. Not read by any script. |
| `Ni_MC.h5` | HDF5 (33 MB) | **Output of `MCNi.nml`.** Electron energy-histogram and exit-angle statistics. **Input to** `02_master_pattern/EMEBSDmaster.nml` and `EMEBSDmaster_hires.nml` (`copyfromenergyfile`), which reuse this Monte Carlo data instead of recomputing it for each master-pattern resolution. |

## `02_master_pattern/` — full-sphere diffraction pattern (EMEBSDmaster)

**Input:** `01_monte_carlo/Ni_MC.h5`
**Output:** `Ni_master.h5` / `Ni_master_hires.h5`, consumed by `03_ebsd_pattern_simulation/`, `04_microstructure_demo/`, and `06_euler_angle_validation/`'s suggested settings

Turns the Monte Carlo electron statistics into the **master pattern**: the
diffraction intensity over the *entire* projection sphere around the
crystal, independent of any specific orientation or detector geometry. This
is the expensive, orientation-agnostic calculation that only needs to be
run once per material/resolution; every simulated EBSD pattern afterwards
is just a re-projection of this same master pattern at a different
orientation.

| File | Type | Description |
|---|---|---|
| `EMEBSDmaster.nml` | EMsoft input deck | Standard-resolution run: `npx=100` (200×200 total pixels), `dmin=0.05` nm. Reads `copyfromenergyfile='01_monte_carlo/Ni_MC.h5'`, reads Bethe cutoffs from `BetheParametersFile='02_master_pattern/BetheParameters.nml'`, writes `energyfile='02_master_pattern/Ni_master.h5'`. Run with `EMEBSDmaster EMEBSDmaster.nml`. |
| `EMEBSDmaster_hires.nml` | EMsoft input deck | High-resolution run: `npx=500` (1000×1000 total pixels), `dmin=0.03` nm — finer angular sampling and smaller d-spacing cutoff, needed for the actual pattern simulations downstream. Writes `energyfile='02_master_pattern/Ni_master_hires.h5'`. This is the file actually used everywhere else in the repo. |
| `EMEBSDmaster.template` | EMsoft input deck (blank) | Generic version (`energyfile='MCoutput.h5'`, `copyfromenergyfile='undefined'`) kept as a reference. Not read by any script. |
| `BetheParameters.nml` | EMsoft input deck | Bethe-potential approximation thresholds used by *both* master-pattern runs above to decide which diffracted beams are "strong" (`c1=4.0`), "weak" (`c2=8.0`), or ignored (`c3=50.0`) during the dynamical diffraction calculation. Referenced by filename from `EMEBSDmaster.nml`/`EMEBSDmaster_hires.nml`. |
| `BetheParameters.template` | EMsoft input deck (blank) | Identical structure, kept as a reference/starting point. |
| `Ni_master.h5` | HDF5 (39 MB) | **Output of `EMEBSDmaster.nml`.** Standard-resolution master pattern. Not consumed further downstream in this repo (the hi-res version is used instead), kept for comparison. |
| `Ni_master_hires.h5` | HDF5 (201 MB) | **Output of `EMEBSDmaster_hires.nml`.** The high-resolution master pattern actually used everywhere downstream: **input to** `03_ebsd_pattern_simulation/EMEBSD.nml` & `EMEBSD_ni.nml` (`masterfile`), `04_microstructure_demo/microstructure_demo.py` (`MASTER_FILE`), and to `view_master.py` below. |
| `view_master.py` | Python script | Opens `Ni_master_hires.h5` with h5py, plots the master pattern, saves `Ni_master.png`. Run as `python view_master.py` from inside this folder. |
| `Ni_master.png` | Image | **Output of `view_master.py`.** Visualization of the master pattern — what the diffraction intensity looks like projected over the full sphere around the crystal, before any detector geometry is applied. |

## `03_ebsd_pattern_simulation/` — simulated detector patterns (EMEBSD)

**Input:** `02_master_pattern/Ni_master_hires.h5` (the diffraction sphere) **+** an angle file (the orientations to render) from either this folder (`angles.txt`, a hand-written test list) or `06_euler_angle_validation/` (`ni_angles.txt`, extracted from the real scan)
**Output:** `Ni_EBSD.h5` / `Ni_EBSD_sim.h5`, consumed by `05_denoising_training_data/` and `06_euler_angle_validation/`

Takes the orientation-agnostic master pattern and projects it onto a
*specific, finite* virtual detector (pixel count, pattern center, sample
tilt, camera distance) at a list of *specific* crystal orientations. This
is the step that produces images that look like what a real EBSD camera
would record.

| File | Type | Description |
|---|---|---|
| `EMEBSD.nml` | EMsoft input deck | A basic/test config: 640×480 detector, `xpc=ypc=0` (centered), reads the 5 test orientations in `anglefile='03_ebsd_pattern_simulation/angles.txt'` and `masterfile='02_master_pattern/Ni_master_hires.h5'`, writes `datafile='03_ebsd_pattern_simulation/Ni_EBSD.h5'`. Used to sanity-check the setup before running the full 4125-orientation job. |
| `EMEBSD_ni.nml` | EMsoft input deck | The real run: 60×60 detector matching the actual experimental camera, `xpc=4.337, ypc=17.273, L=1500.8` (pattern center values obtained from `06_euler_angle_validation/02_get_pc.py`), reads all orientations from `anglefile='03_ebsd_pattern_simulation/ni_angles.txt'`, writes `datafile='03_ebsd_pattern_simulation/Ni_EBSD_sim.h5'`. This is the run whose output is later compared against the real scan. |
| `EMEBSD.template` | EMsoft input deck (blank) | Generic version (`anglefile='testeuler.txt'`, `masterfile='master.h5'`, `datafile='EBSDout.h5'`), kept as a reference. |
| `angles.txt` | Text (5 lines) | Hand-written Euler-angle test list, consumed by `EMEBSD.nml`. Not derived from data — just a quick smoke test. |
| `ni_angles.txt` | Text (4125 lines as of the current `nickel_ebsd_large` data; will grow to ~29,800 lines once regenerated from `ni_gain(1)`) | **Copy of the output of** `06_euler_angle_validation/03_extract_euler_angles_from_patterns.py`. One Euler-angle triplet per real scan point, in the same row-major order as the real scan grid. **Input to** `EMEBSD_ni.nml`. |
| `Ni_EBSD.h5` | HDF5 (944 KB) | **Output of `EMEBSD.nml`.** 5 simulated patterns from the smoke test. **Input to** `view_patterns.py` below. |
| `Ni_EBSD_sim.h5` | HDF5 (15 MB currently) | **Output of `EMEBSD_ni.nml`.** One simulated pattern per real scan point, in the same order — will grow ~7x once regenerated against the larger `ni_gain(1)` dataset. **Input to** `05_denoising_training_data/make_noise.py` (the "clean" half of each training pair) and to every comparison script in `06_euler_angle_validation/` (`04_pc_check.py`, `05_side_by_side.py`, `06_diagnose_match.py`). |
| `view_patterns.py` | Python script | Opens `Ni_EBSD.h5`, plots a few of the 5 test patterns, saves `Ni_patterns.png`. Run as `python view_patterns.py` from inside this folder. |
| `Ni_patterns.png` | Image | **Output of `view_patterns.py`.** Visual check of what the smoke-test patterns look like. |

## `04_microstructure_demo/` — synthetic grain map demo

**Input:** `02_master_pattern/Ni_master_hires.h5`
**Output:** three standalone images (not consumed by any later stage — this is a self-contained illustration, not part of the validation chain)

Does not use any real or EMsoft-simulated scan data. Instead it invents a
fake polycrystalline microstructure (a grid of random grains with random
orientations) and uses the master pattern to render what each grain's EBSD
pattern would look like, purely to illustrate the concept of a grain map
and IPF coloring.

| File | Type | Description |
|---|---|---|
| `microstructure_demo.py` | Python script | Generates ~12 synthetic grains over a 40×40 pixel map, assigns each a random orientation, loads `../02_master_pattern/Ni_master_hires.h5` via kikuchipy to render a pattern for each grain, and builds an IPF-colored orientation map from the random orientations. |
| `micro_example_patterns.png` | Image | **Output.** Sample simulated patterns, one per synthetic grain. |
| `micro_grain_map.png` | Image | **Output.** The synthetic grain/orientation map (spatial layout of the fake grains). |
| `micro_ipf_colorkey.png` | Image | **Output.** The IPF color-key legend used to interpret `micro_grain_map.png`. |

## `05_denoising_training_data/` — paired clean/noisy training data

**Input:** `03_ebsd_pattern_simulation/Ni_EBSD_sim.h5` (clean simulated patterns) **+** `06_euler_angle_validation/patterns.h5` (real scan, used to calibrate/reference the noise level)
**Output:** `training_pairs.h5` (end product — not consumed elsewhere in this repo, presumably the input to a separate ML denoising model)

Builds a dataset for training a pattern-denoising model: each clean,
noise-free simulated pattern from `03` is paired with a version of itself
that has calibrated noise added, so a network can learn to map
noisy → clean.

| File | Type | Description |
|---|---|---|
| `make_noise.py` | Python script | Loads clean patterns from `../03_ebsd_pattern_simulation/Ni_EBSD_sim.h5` and the real scan `../06_euler_angle_validation/patterns.h5` (used to calibrate realistic noise statistics), applies Poisson + Gaussian noise in one of two modes (`calibrated` matches the real scan's noise level, `paper` uses fixed literature values), writes clean/noisy pairs to `training_pairs.h5`, and saves a visual comparison. |
| `noise_check.png` | Image | **Output.** Three rows: real pattern (top), clean simulated pattern (middle — what the network sees as input), and noise-added simulated pattern. Used to sanity-check that the synthetic noise resembles the real detector's noise. |
| `training_pairs.h5` | HDF5 (94 MB) | **Output.** The paired clean/noisy patterns dataset. |

## `06_euler_angle_validation/` — ground truth extraction & simulation validation

**Input:** none from earlier stages except `Ni_EBSD_sim.h5` (fed back in for comparison) — this folder's own `patterns.h5` is the true starting point of the whole repo, obtained independently of EMsoft
**Output:** `ni_angles.txt` (fed forward into `03_ebsd_pattern_simulation/EMEBSD_ni.nml` as its `anglefile`) **and** a set of comparison figures that judge whether the simulation matches reality

This folder does two jobs that bookend the rest of the pipeline:

1. **Before `03` runs:** extract the real scan's known orientations and
   detector geometry, so `EMEBSD_ni.nml` can be configured to reproduce
   that exact scan.
2. **After `03` runs:** compare the resulting simulated patterns
   (`Ni_EBSD_sim.h5`) against the real ones (`patterns.h5`) to check
   whether EMsoft's simulation actually agrees with the real
   measurement — same axis conventions, same pattern center, same
   band positions.

Scripts are **numbered in run order** (see this folder's own
[`README.md`](06_euler_angle_validation/README.md) for the exact sequence,
including the external EMsoft step that runs between step 3 and step 4).
All generated figures are collected in `outputs/`; `patterns.h5`,
`ni_angles.txt`, and `ni_angles_map.csv` stay at the folder's top level
since they're pipeline data, not diagnostic images.

| File | Type | Description |
|---|---|---|
| `01_download_data_patternsh5.py` | Python script | Downloads the real experimental dataset via kikuchipy (currently `ni_gain(1)`, 149×75 → 29,800-point Ni EBSD scan, 60×60 px patterns, already indexed by conventional means) and saves it as `patterns.h5`. |
| `patterns.h5` | HDF5 | The real experimental scan. **The ground truth the whole pipeline is trying to reproduce.** Consumed by every script below, by `03_ebsd_pattern_simulation` indirectly (via the angle file extracted from it), and by `05_denoising_training_data/make_noise.py`. |
| `02_get_pc.py` | Python script (**step 2**, run before EMEBSD) | Reads `patterns.h5`'s recorded detector geometry and converts it into EMsoft's pattern-center convention (`xpc`, `ypc`, `L`, `delta`). **Output consumed manually**: these numbers get pasted into `03_ebsd_pattern_simulation/EMEBSD_ni.nml`. |
| `03_extract_euler_angles_from_patterns.py` | Python script (**step 3**, run before EMEBSD) | Extracts every indexed orientation from `patterns.h5`, converts to degrees, and writes `ni_angles.txt` in EMsoft's angle-file format plus `ni_angles_map.csv` for row/col lookup. Also prints suggested `EMEBSD.nml` settings (`masterfile`, `datafile`, detector size) matching the source scan. **Output (`ni_angles.txt`) must be copied to `03_ebsd_pattern_simulation/` and used as `EMEBSD_ni.nml`'s `anglefile` — this is the hand-off point from "real data" into "simulation".** |
| `ni_angles.txt` | Text | **Output of `03_extract_euler_angles_from_patterns.py`.** Local copy (identical to the one in `03_ebsd_pattern_simulation/`). |
| `ni_angles_map.csv` | CSV | **Output of `03_extract_euler_angles_from_patterns.py`.** Maps each angle-file line number to its (row, col) position on the scan grid, so simulated patterns can be placed back on the map. |
| *(external step)* | — | Run `EMEBSD EMEBSD_ni.nml` from `03_ebsd_pattern_simulation/` to (re)produce `Ni_EBSD_sim.h5` before running the scripts below. |
| `04_pc_check.py` | Python script (**step 4**, run after `EMEBSD_ni.nml`) | Compares a handful of real vs. simulated patterns side by side at the same scan points, to check whether the pattern center (`xpc`/`ypc`/`L`) chosen in `EMEBSD_ni.nml` puts the diffraction bands in the right place. → `outputs/pc_check.png` |
| `05_side_by_side.py` | Python script (**step 5**) | Builds IPF-colored orientation maps from both `patterns.h5` (real) and `Ni_EBSD_sim.h5` (simulated) and compares them directly, along with a numeric max-color-difference check (should be ~0 since both come from the same underlying orientations). → `outputs/ipf_real_vs_sim.png` |
| `06_diagnose_match.py` | Python script (**step 6**) | If patterns don't match, tests whether a simple flip/rotation/transpose of the simulated patterns brings them into agreement (EMsoft and kikuchipy don't always agree on "which way is up"), scoring each candidate transform by normalized cross-correlation over many scan points. → `outputs/diagnose_match.png` |
| `07_visualize_ebsps.py` | Python script (general, needs only `patterns.h5`) | Produces four diagnostic views of the raw patterns: an evenly-sampled montage, a raw-vs-background-removed comparison, every pattern tiled at its map position, and an IPF map with sample patterns pinned to their locations. → `outputs/ebsp_montage.png`, `outputs/ebsp_raw_vs_proc.png`, `outputs/ebsp_mosaic.png`, `outputs/ebsp_with_map.png` |
| `08_visualize_IPF_colored_map.py` | Python script (general) | Builds a single IPF-Z colored orientation map from either the real or simulated data (toggle by which `kp.load(...)` line is active). → `outputs/ipf_z_map_with_key_sim.png` |
| `outputs/` | Folder | All PNGs generated by the scripts above, collected in one place instead of scattered alongside the scripts. |

## External configuration this pipeline depends on

`~/.config/EMsoft/EMsoftConfig.json` sets the two path roots every `.nml`
file's relative filenames are resolved against:

```json
"EMXtalFolderpathname": "/home/azza_osman/EMsoftData_work/00_crystal_structure/",
"EMdatapathname":       "/home/azza_osman/EMsoftData_work/"
```

If this repo is ever moved to a different location, both values must be
updated to match, or every EMsoft run will fail to find its input files.
