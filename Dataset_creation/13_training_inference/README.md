# 13 — Training & inference (EBSD denoising VAE)

Trains a VAE to map **noisy → clean** 128×128 IPF orientation maps, using the
PNG pairs generated by the DREAM3D pipelines in [`../12_dream3d`](../12_dream3d).

| File | Role |
|---|---|
| `dataset.py` | `EBSD_Dataset` — pairs each clean PNG with the same-named noisy PNG |
| `architecture.py` | `EBSD_VAE` + `vae_loss_function` |
| `train.py` | Training loop; saves `ebsd_vae_weights.pth` next to the code |
| `inference.py` | Runs a trained model on new maps |
| `train_model.sh` | SLURM submit script for this cluster |

## Where the dataset lives

**Outside the git repo**, at:

```
/project/community/aiosman/datasets/ni_vae/clean/
/project/community/aiosman/datasets/ni_vae/noisy/
```

Deliberately not under `Dataset_creation/` — 80,000 PNGs in the working tree
invites accidental commits and slows down every git operation. `train.py` already
points at these two paths.

**Filenames must match across the two directories.** `dataset.py` lists `clean/`
and then opens *the same filename* from `noisy/`, so `clean/Map_00001.png` pairs
with `noisy/Map_00001.png`. A mismatch (`Map_00001_noisy.png` and so on) fails
with `FileNotFoundError` on the first batch, not with a helpful message.

## Uploading the data from the Windows/WSL side

The maps are generated on Windows and this cluster isn't reachable as a network
path from there, so they have to come over SSH. Tar first — 80,000 tiny files
transferred individually is dominated by per-file overhead and takes far longer
than moving one archive of the same bytes:

```bash
# in WSL, from the parent of the two map folders
tar czf ni_dataset.tar.gz ni_clean_maps ni_noisy_maps
rsync -avP ni_dataset.tar.gz aiosman@orchard-login-001:/project/community/aiosman/datasets/

# then on the cluster
cd /project/community/aiosman/datasets
tar xzf ni_dataset.tar.gz && rm ni_dataset.tar.gz
# move/rename the extracted folders to ni_vae/clean and ni_vae/noisy
```

`rsync -P` is resumable, so a dropped connection doesn't restart from zero.

For scale: a 128×128 IPF PNG is ~2.8 KB, so 40,000 clean + 40,000 noisy is only
about **225 MB** — a couple of minutes. The `.dream3d` (~674 KB) and Euler `.txt`
(~513 KB) files per map are much larger in aggregate, and the training code
doesn't read them, so don't ship those.

## Running it

```bash
sbatch /project/community/aiosman/Dataset_creation/13_training_inference/train_model.sh
```

Cluster-specific things baked into that script, all of which differ from the
generic defaults it started with:

- **`--partition=general --qos=general_qos --gres=gpu:1`** — there is no `gpu`
  partition here. `--time=12:00:00` is the general partition's maximum.
- **No `module load`** — this cluster has no python/cuda modules. The script calls
  `~/miniconda3/envs/diffusion/bin/python` directly, which has torch 2.12.1+cu130,
  torchvision and PIL. `conda activate` is avoided on purpose: it needs a shell
  hook that isn't initialized inside a batch job.
- Remember the QOS caps you to **one running job at a time**, so a training run
  and an EMsoft batch job can't overlap.

Logs land in `/project/community/aiosman/logs/vae_train_<jobid>.{out,err}`.
